# UDP Game Protocol / DUSTLINE

Репозиторий последовательно объединяет семь сетевых практик. Первые три строят консольный UDP-протокол на C#/.NET. Следующие четыре развивают игру DUSTLINE на Unity, добавляя prediction, оптимизацию репликации, шифрование и выделенный сервер.

## Практическая работа №1. Бинарный UDP-протокол
Авторитетный UDP-сервер принимает бинарные команды движения и стрельбы, проверяет их и возвращает клиенту вычисленное состояние.
- [Документы, демонстрация, спецификация и скриншоты](docs/practice-01-udp-protocol/)
- [Исходный код](src/) · [методичка](<Практическая работа №1.pdf>)

## Практическая работа №2. Задержка, джиттер и потери
Эксперименты PING/PONG измеряют сетевую задержку, её изменение во времени и долю потерянных пакетов в заданных профилях.
- [Отчёты, условия эксперимента, графики и CSV](docs/practice-02-network-metrics/)
- [Методичка](<Практическая работа 2.pdf>)

## Практическая работа №3. Надёжная доставка поверх UDP
Команды стрельбы подтверждаются отдельным ACK и автоматически повторяются при потере. Адаптивный RTO и серверная дедупликация предотвращают лишние повторные игровые эффекты.
- [Документы, графики, данные, логи и скриншоты](docs/practice-03-reliable-delivery/)
- [Код надёжности](src/UdpGame.Reliability/) · [тесты](tests/UdpGame.Reliability.Tests/)

## Практическая работа №4. Предсказание и коррекция движения
Unity-игра DUSTLINE сразу показывает предсказанное движение локального игрока и затем сверяет его с авторитетным состоянием сервера. Также описаны стрельба, испытания при потерях и визуальное обновление.
- [Документация, матрицы, скриншоты и тестовые результаты](docs/practice-04-client-prediction/)
- [Unity-исходники и инструкция запуска](https://github.com/teeeema/udp-csharp/tree/44f28e3e5af611c3ad1c36b229648c18bba12a2d)

## Практическая работа №5. Оптимизация репликации
ПР5 измеряет объём сетевых обновлений игровых объектов до и после оптимизации с учётом дистанции и частоты обновления.
- [Отчёты, методика, исходные данные и тесты](docs/practice-05-replication/)

## Практическая работа №6. Шифрование игрового транспорта
Игровые датаграммы защищены AES-GCM. Ключи направлений выводятся из X25519. Работа описывает проверки целостности, результаты тестов, модель угроз и захваты Wireshark.
- [Unity-проект и инструкция запуска](unity/PredictionDemo/)
- [Код шифрования](unity/PredictionDemo/Assets/Scripts/Prediction/Security/)
- [Отчёт и аудит требований](unity/PredictionDemo/docs/PR6_Report.md) · [захваты Wireshark](unity/PredictionDemo/docs/pr6-wireshark-2026-11-21/)

## Практическая работа №7. Dedicated Server, Docker и Steam
Linux-сервер Unity запущен в Docker на Ubuntu, для него подготовлен Windows-клиент и интеграция Steam. Два клиента прошли игровой тест по локальной сети. Итоговая матрица содержит 19 PASS и 9 BLOCKED.
- [Проект, инструкции, результаты и доказательства](unity/DedicatedServer/)
- [Отчёт и результаты T01–T28](unity/DedicatedServer/docs/pr7/FINAL_REPORT.md) · [план тестирования](unity/DedicatedServer/docs/pr7/TEST_RESULTS.md)

## Консольное решение
Для работ 1–3 установите .NET SDK 10.0. В корне репозитория выполните:

    dotnet build UdpGame.sln
    dotnet test UdpGame.sln --no-build
