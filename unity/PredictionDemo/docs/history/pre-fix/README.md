# DUSTLINE — практическая работа №5

Unity-адаптация оптимизации репликации. Основа — реально сохранившийся проект ПР4; аудит: [docs/Recovery_Audit.md](docs/Recovery_Audit.md).

## Запуск

macOS Apple Silicon; Unity 6000.6.7f1, NGO 2.13.3, Unity Transport 6.6.0, URP 17.6.0. Откройте этот каталог через Unity Hub, затем Assets/Scenes/PredictionDemo.unity. Пакет Pipeline встроен локально для воспроизводимости работы CLI. Первый импорт может занять несколько минут.

Готовое приложение: Builds/ReplicationLab.app. В редакторе prefab создаётся через PR5 → Create replication prefab, сборка — PR5 → Build macOS. Сборщик сохраняет исходную игровую сцену.

Два независимых процесса из Terminal (путь исполняемого файла смотрите в Builds/ReplicationLab.app/Contents/MacOS):

```sh
./Builds/ReplicationLab.app/Contents/MacOS/PredictionDemo --pr4-host
./Builds/ReplicationLab.app/Contents/MacOS/PredictionDemo --pr4-client
```

Если имя исполняемого файла отличается, используйте фактическое имя; Tools/run_experiment.py определяет его автоматически. WASD — движение, Space — рывок, F/ЛКМ — стрельба, B — намеренно неверно предсказанный рывок. Клавиша F3 открывает прежнюю диагностическую панель ПР4 (точную привязку см. TankGameHud.cs). Панель ПР5 слева под заголовком показывает режим, число props, видимость для первого удалённого клиента, игроков и TX/RX. Host может переключать режим кнопкой без перезапуска. Для чистого сравнения рекомендуется новая сессия с флагом --optimized на обоих процессах. Серверная кнопка Dedicated server запускает сервер без локального игрока, порт 7777. Адрес для удалённого клиента задаётся в панели ПР4; в автоматических опытах используется 127.0.0.1.

50 props: 20 неподвижных ящиков, 15 движущихся мишеней, 10 индикаторов состояния, 5 подбираемых предметов. Цвета: серый, красный, голубой, жёлтый. Сервер рассчитывает движение, здоровье, попадания и подбор; предмет удаляется при приближении игрока. Клиент не задаёт здоровье или позицию объекта. Игроки всегда реплицируются независимо от релевантности props.

## Повторение эксперимента

```sh
python3 Tools/run_experiment.py
python3 Tools/run_verification.py
```

Первый сценарий запускает Host + Client дважды, 48 с на процесс, анализирует секунды 10–40 (30 секундных отсчётов) без движения и искусственных потерь. Он перезаписывает CSV текущего прогона. Второй перемещает тестовую мишень в/из зоны видимости, меняет здоровье в скрытом состоянии, возвращает и удаляет её; клиент стреляет. Логи и скриншоты сохраняются в docs/verification. Не запускайте сценарии одновременно с другими сессиями на том же порту.

Метрики — фактические байты NGO на входе/выходе UnityTransport, KB=1000 B. Они исключают заголовки UDP/IP, транспортные ACK и повторы: это не полный wire-трафик. Игровые метрики не моделируются.
