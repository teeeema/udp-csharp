# Замечания аудита

Исходный проект не исправлялся. Номера строк относятся к оригинальному Practice5Replication. Для каждого пункта ниже отделяются подтверждённый код и динамический результат; итоговые измерения и статусы — в Audit_Report.md.

## HIGH — H01. Сервер применяет каждую команду движения без бюджета времени

**Код:** Assets/Scripts/Prediction/PredictedPlayer.cs:205–230. RPC ограничен владельцем, однако проверяются только возрастающий sequence и направление. Каждый запрос применяет MoveSpeed × TickDelta, независимо от частоты поступления. Нет server tick budget, ограничения количества вводов за интервал или проверки конечности float.

**Воспроизведение:** отдельный клиент посылает 500 разрешённых владельцу SubmitInputRpc с возрастающими номерами за один кадр. Диагностический модуль не меняет ProcessServerInput; вызывает тот же RPC-путь через reflection только на принадлежащем клиенту персонаже. Ожидается ограничение серверной скоростью 4 м/с. Динамический результат см. speed-*-host.state и соответствующие логи.

**Последствие:** сервер формально вычисляет позиции, но не обеспечивает допустимую скорость. При NaN/Infinity дополнительных защит также нет (случай не посылался, вывод по коду).

**Исправление:** серверная симуляция по своим тикам, ограниченная очередь ввода и скорость обработки; проверка finite, допустимого окна sequence, кулдаунов и владения. Добавить отдельный сетевой тест превышения частоты RPC.

## HIGH — H02. Новая сессия в той же сцене не восстанавливает нагрузку

**Код:** Assets/Scripts/Prediction/Replication/ReplicationLab.cs:12,35–40. `spawned` устанавливается один раз и не сбрасывается при Shutdown. После уничтожения spawned objects новая StartHost/StartServer не создаёт 50 props. Динамическая проверка — restart-*-host.log/state: до перезапуска 50, после 0 в обоих режимах.

**Воспроизведение:** запустить Host, дождаться 50 объектов, Shutdown, затем StartHost без перезагрузки сцены. Ожидается полноценная новая сессия с 50 объектами.

**Исправление:** очищать состояние сессии через серверные callbacks, заново создавать нагрузку после старта; добавить автоматический цикл Start → Stop → Start с удалённым клиентом.

## HIGH — H03. Урон применяется до выбора ближайшего попадания

**Код:** Assets/Scripts/Prediction/TankWeapon.cs:80–101. Physics.Raycast сначала находит prop и вызывает Damage, после чего код может выбрать более близкий танк по Bounds. Коллайдеров у танков нет. Объект за танком получает урон, даже если итоговый hitName равен tank.

**Воспроизведение:** серверный стрелок x=100,z=0, второй танк x=100,z=5, мишень x=100,z=10, стрелять вдоль +Z. Диагностический модуль располагает объекты для воспроизводимого ray test и вызывает существующий FireRpc. Ожидается отсутствие урона закрытой мишени. Первые standalone fixtures не попадали в мишень и не засчитываются как доказательство. Контролируемый локальный серверный probe с Physics.SyncTransforms подтвердил 100 → 90 при ожидаемых 100: evidence/occlusion-direct-probe-final.json. Это тест серверной геометрии с двумя сетевыми танками, а не отдельная проверка удалённой доставки.

**Исправление:** сначала выбрать ближайший результат среди physics hits и tank bounds, затем применить единственный игровой эффект выбранной цели.

## MEDIUM — M01. Счётчик RX дублирует подписку после повторного Initialize

**Код:** Assets/Scripts/Prediction/Replication/MeteredTransport.cs:7. Подписка OnTransportEvent += Count не снимается; счётчики не сбрасываются на новую сессию. Две Initialize дают два вызова Count для одного входящего payload. Доказательство — evidence/meter-reinitialize-probe.json.

**Исправление:** одна подписка на время жизни компонента либо симметричные Initialize/Shutdown; отдельно сбрасывать epoch/счётчики и проверять TX/RX после переподключения.

## MEDIUM — M02. Материалы накапливаются при скрытии/появлении

**Код:** Assets/Scripts/Prediction/Replication/ReplicatedProp.cs:33–35. `renderer.material` создаёт экземпляр материала; собственный экземпляр не освобождается при Despawn/Destroy. Частые NetworkHide/Show создают новые объекты и материалы.

**Доказательство:** поля `materials` и `memory` в matrix-*.state до, во время и после серии переключений t=66–72. Рост количества materials сохраняется после возвращения к стабильному режиму. Это не доказательство неограниченного роста всей памяти за часы, но конкретные лишние native Material остаются.

**Исправление:** MaterialPropertyBlock для цвета или явное владение и Destroy созданного Material в OnDestroy; отдельный тест 100 циклов hide/show.

## MEDIUM — M03. RPC снимков не защищены от устаревания

**Код:** Assets/Scripts/Prediction/Replication/ReplicatedProp.cs:10,32,37–38. SnapshotRpc — Unreliable, без монотонного номера/проверки phase. Обработчик игнорирует hp и phase, сохраняет любой полученный Vector3. Старый RPC может перекрыть свежую Position на период до 1 с. Реальная перестановка UDP-снимков специально не индуцировалась; отсутствие защиты подтверждено кодом.

**Исправление:** timestamp/sequence с отбрасыванием устаревших снимков, один согласованный источник визуального состояния и интерполяционный буфер. После этого тест перестановки и больших потерь.

## MEDIUM — M04. Профиль BASELINE заведомо избыточен; вывод ограничен моделью нагрузки

**Код:** ReplicatedProp.cs:24–27,38. Позиция и phase отправляются через NetworkVariable и RPC; hp и phase передаются в RPC, но не используются в обработчике. Все статичные props получают periodic full snapshot до 30 Hz. Это явно описано в старом отчёте, поэтому само по себе не является фальсификацией, но разница не измеряет оптимизацию типичного штатного NGO-сценария.

**Исправление:** сохранить текущий сценарий как naive full-state baseline, добавить NGO-native baseline без бесполезных/дублирующих полей и ablation (только relevance / только cadence / вместе). Публиковать отдельные результаты для спокойной и активной нагрузки.

## MEDIUM — M05. Не все 108 проверок являются независимыми тестами

**Код:** Tools/run_verification.py:14–35; docs/Testing_Report.md. 97 framework tests + 11 boolean predicates по одному запуску. `client_received_current_health_after_reentry` и `object_reappeared_current_state` существенно перекрываются; server event strings не доказывают обработку на клиенте. Проверка исключений перечисляет только три типа. Отсутствует жёсткая проверка exit codes/полноты соединения в run_experiment.py.

**Исправление:** отдельно считать framework tests, сценарии и assertions; структурированные id/state ACK от каждого клиента; падать при неполном подключении и ошибке процесса; проверять все runtime errors. Не представлять 108 как 108 независимых игровых/сетевых сценариев.

## MEDIUM — M06. Документация говорит «без задержки», но профиль по умолчанию Lag100

**Код:** Assets/Scripts/Prediction/NetworkLabSettings.cs:34; Tools/run_experiment.py:20. Скрипт не передаёт --pr4-profile 0. Профиль затрагивает только старые игровые RPC, не props, поэтому idle-результат от этого практически не меняется; описание конфигурации всё равно неточное. В текущих независимых опытах профиль 0 задаётся явно.

**Исправление:** явно задавать профиль 0 в baseline/optimized и сохранять разрешённые параметры сети в JSON результата.

## MEDIUM — M07. Релевантность применяется после первоначального spawn

**Код:** ReplicationLab.cs:35–49. Все объекты Spawn с observers по умолчанию; скрытие начинается в периодическом Update, CheckObjectVisibility не задан. Поздний клиент первоначально получает дальние объекты, затем hide. Постоянная дистанционная фильтрация работает, стартовый пик этим не устранён.

**Исправление:** CheckObjectVisibility или SpawnWithObservers=false с выбором начальных наблюдателей, согласовать начальный spawn и периодическое обновление.

## LOW — L01. Заявленные 30/5/2 Hz — целевые интервалы, не всегда достигнутая частота

**Код:** ReplicatedProp.cs:21–22. `next=now+interval` на Update без компенсации пропущенных интервалов. Реальная частота зависит от кадров и может быть ниже. Панель показывает конфигурацию. Квантование округляет float32, но не уменьшает wire-размер Vector3; стандартное dirty-tracking NGO не новая технология.

**Исправление:** подписывать значения как target Hz, измерять реальную частоту по объекту/типу, отдельно документировать порог и упаковку.

## LOW — L02. Ограниченные диагностические и формальные возможности

Панель показывает visible только первого удалённого клиента; O(objects × clients) без spatial grid и без hysteresis. Направление взгляда не учитывается. Архив не включает готовую .app, поэтому его получателю нужен Unity для сборки; необходимые исходники для сборки присутствуют. .DS_Store несущественны. Формальный Unreal Network Profiler / Replication Graph / GitVerse workflow этой Unity-версией не выполнен буквально.

**Исправление:** таблица видимости на клиента, hysteresis при необходимости, подписи ограничений; отдельная поставка .app или явное указание source-only архива. Согласовать Unity-адаптацию с преподавателем.
