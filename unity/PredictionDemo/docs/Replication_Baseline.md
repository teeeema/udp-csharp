# BASELINE после исправлений — 06.11.2026

Unity 6000.6.7f1, NGO 2.13.3, Transport 6.6.0, URP 17.6.0; macOS Apple Silicon. Два отдельных процесса одной development-сборки, Host + один Client, 50 серверных props, profile 0. Сессия каждого режима — 120 с после старта сетевой роли. BASELINE и OPTIMIZED запускались последовательно; во время замеров другие сетевые диагностики не выполнялись. Сценарии задаются одинаковыми временными интервалами и кнопками. Реальное число выстрелов может немного отличаться из-за кадровой дискретизации и серверного cooldown. Измеряется NGO payload, KB=1000 байт, а не UDP wire-трафик; UTP ACK/повторы/UDP-IP заголовки исключены.

Окна по общим часам NGO ServerTime: покой 8–18 с; Client 21–31; оба 33–43; стрельба 45–55; состояния 57–67; зоны 69–95; комбинация 101–115. Начальная синхронизация исключена. Средняя скорость = разность накопленных байтов / фактическая длительность окна / 1000. Скрипт отклоняет окно, если не видит двух игроков. Сырые счётчики и входящий поток Client находятся в final-results/*.state и *.csv; агрегат — final-results/traffic-summary.json. Целевые частоты props 30 Hz / 5 Hz / 2 Hz, фактические ограничены Update/FPS.

BASELINE посылает полный снимок всех 50 props каждому клиенту до 30 Hz, без distance culling и static sleep. Это намеренно наивная нагрузка: Position/Phase частично дублируются через NetworkVariable и SnapshotRpc. Это не штатный оптимальный NGO baseline и не profiler breakdown по каждому актору. В обоих режимах штатный dirty tracking NGO уже работает.
