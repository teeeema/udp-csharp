# Соответствие методичке №5

Первичный источник: «Практическая работа №5.pdf», обе страницы. Все требования ниже относятся к функциональной Unity-адаптации; Unreal Engine буквально не используется.

| Требование | Реализация | Оценка |
|---|---|---|
| Listen Server и клиент | NetworkBootstrap, NGO StartHost/StartClient; сборка ReplicationLab.app | ПОДТВЕРЖДЕНО |
| ≥50 реплицируемых акторов | ReplicationLab.Update создаёт 50 ReplicatedProp с NetworkObject; серверные NetworkVariable | ПОДТВЕРЖДЕНО |
| Все объекты всем клиентам в baseline | Optimized=false, без NetworkHide; full SnapshotRpc до 30 Hz | ПОДТВЕРЖДЕНО |
| Исходящий профиль, частота обновлений | MeteredTransport.Send, CSV секундных дельт; частота задана ReplicationPolicy | ЧАСТИЧНО ПОДТВЕРЖДЕНО: payload-байты, без полного wire-профиля и UI Unity Profiler |
| Определение тяжёлых акторов | Полная рассылка SnapshotRpc; все 50 включены; анализ кода, без отдельного profiler breakdown на тип | ЧАСТИЧНО ПОДТВЕРЖДЕНО |
| Минимум две оптимизации | Репликация по дистанции через NetworkShow/Hide; 5/2 Hz для второстепенных объектов; static sleep | ПОДТВЕРЖДЕНО |
| Replication Graph / Grid Spatialization | Линейный проход по 50 объектам и наблюдателям вместо сеточного UE Replication Graph | ЧАСТИЧНО ПОДТВЕРЖДЕНО: функциональная дистанционная релевантность, не буквальная сетка |
| Net Dormancy | Отключена периодическая SnapshotRpc/Phase статичных props; начальное состояние и изменения здоровья сохраняются в NGO variables | ПОДТВЕРЖДЕНО как аналог сна |
| Push-Based Replication | Штатная dirty-репликация NetworkVariable существовала в обоих режимах; самостоятельной оптимизацией не считается | ПОДТВЕРЖДЕНО разграничение |
| Квантование | Позиции округляются до 0,1 м; порог уменьшает изменения. Vector3 остаётся float32, упаковка до int16 не реализована | ЧАСТИЧНО ПОДТВЕРЖДЕНО; экономия размера координат не заявляется |
| Снижение NetUpdateFrequency | ReplicationPolicy.Interval: baseline 30 Hz, optimized мишени 5 Hz, индикаторы 2 Hz | ПОДТВЕРЖДЕНО |
| Повторный профиль в тех же условиях | Tools/run_final_validation.py; одинаковая сборка, карта, число игроков, длительность, сценарий | ПОДТВЕРЖДЕНО |
| Таблица до/после, KB/s, объекты, объяснение | [Replication_Baseline.md](Replication_Baseline.md), [Replication_Optimization.md](Replication_Optimization.md), исходные CSV | ПОДТВЕРЖДЕНО |
| Ориентир 40–60% | Фактический результат указан в отчёте; ориентир не является обязательным диапазоном | См. измерения |
| Доп.: дистанция и направление взгляда | Только дистанция, без FOV | ЧАСТИЧНО ПОДТВЕРЖДЕНО |
| Доп.: приоритеты игровых событий | Игроки и надёжные FireRpc вне фильтра props; здоровье идёт штатной NGO-репликацией | ПОДТВЕРЖДЕНО как функциональный аналог, не UE NetPriority |
| netprofile enable, Network Profiler Unreal | Не доступны в Unity | ОПРОВЕРГНУТО буквальное выполнение; заменены измерениями payload |

Соответствие ПР4: PredictedPlayer передаёт ввод, проверяет его сервером, хранит pending и повторяет ввод после коррекции. PredictionRules и TankWeapon проверяют кулдауны и владение. Эти исходники сохранены. Полная старая матрица задержек/потерь ПР4 заново не выполнена; данные старых отчётов не объявляются новым результатом.

Ограничения: distance-проход O(objects × clients) подходит для 50 объектов, но не заменяет production spatial index. Релевантность оценивается раз в 0,2 с, без гистерезиса, поэтому у границы возможны spawn/hide. 0,1 м — округление, не сжатый wire-формат. Полный профиль Wireshark/Profiler и большие WAN-нагрузки не сняты. Формальное принятие Unity вместо Unreal Engine не гарантируется.
